# Gou Min 个人网站与创作后台产品方案

这是本次里程碑的产品边界与验收标准。网站服务访客、招聘者和技术同行；Studio 服务内容维护者。两者共享内容模型，但不共享信息密度和操作入口。本文中 P0—P3 均已有可验收实现；后续迭代应继续守住这些边界。

## P0 · 可靠发布

目标：任何一次编辑都可恢复，发布结果可解释。

- 编辑器输入后以防抖方式保存本地恢复快照，离开页面前再保存一次。
- 普通保存保持服务器当前发布状态；已发布内容只能通过显式“撤回发布”下线。
- 标题、日期、摘要、分类、系列、标签和正文在提交前校验；错误信息指出字段和修复方法。
- 发布状态展示“提交、排队、构建、上线、失败”，失败时提供日志入口；生产域名 SHA marker 未与快照一致时不得显示成功。
- GitHub 模式使用提交 SHA 做并发保护；本地模式覆盖或删除前生成私有备份。
- 本地备份和待同步快照使用 `0700` 目录与 `0600` 文件，并通过私有 iCloud Drive 保留一份离机副本。
- 历史弹窗可以读取 Git 提交或本地备份，显示与当前编辑正文的逐行差异后再恢复。
- Mac launchd 单例 worker 从持久队列恢复中断任务，在 detached worktree 构建不可变提交快照，并推送同一 SHA。

验收：断网/关闭页面后可恢复未提交内容；覆盖和删除均有本地与离机恢复路径；普通保存不意外改状态；发布失败或生产 SHA 不一致不显示为成功。

## P1 · 内容工作流

目标：导入、编辑、预览、发布是一条连续流程。

- 每个内容模块都有列表、搜索、状态筛选、新建、导入、编辑和预览入口。
- 编辑器提供 Markdown 当前内容预览、显式状态操作、本地权威定时发布、版本差异和删除保护。
- 常用 frontmatter 使用结构化控件；分类、系列和标签关联可以从已有项中点选。
- 正文素材可以在编辑器内检索或上传，填写替代文本后直接插入 Markdown。
- 总览支持按状态、类型、健康度筛选，并支持批量转草稿、待发布和发布。
- 导入统一经过字段校验、正文安全渲染和同名冲突检查。

验收：博客、项目、随记、书影音、关于页均能完成导入/编辑/预览/发布回读；用户无需编辑 JSON 即可完成日常元数据和图片工作。

## P2 · 个人品牌与招聘者路径

目标：访客在三分钟内理解个人方向、代表项目和联系方式。

- 首页首屏给出身份、领域、代表项目和联系入口。
- 项目页采用“背景—职责—方案—取舍—结果—链接”结构。
- 关于页承载个人介绍，首页和项目页直接提供代表成果与联系入口。
- 顶部导航保持精简，不再提供独立简历页面。

验收：访客可从首页进入代表项目、关于页并直接联系；前台不存在独立简历路由或入口。

## P3 · 可持续增长

目标：在不引入隐私风险的前提下，了解内容质量和网站健康度。

- Studio 分析页展示内容规模、发布趋势、健康度和模块分布，不默认采集访客身份。
- 保留 RSS、站内搜索、相关推荐和可选评论适配器；评论只有在配置完整时启用。
- 中英文 UI 沿用现有 catalog 机制，新增页面必须提供中文回退。
- 构建验证、链接检查、内容审计和回滚能力纳入 CI。
- Vercel 只发布公共静态产物；Studio、Keystatic、预览路由、API、服务端函数和不可达后台依赖不进入生产产物。
- Studio GitHub OAuth 只接受精确的 `https://studio.goumin.work/api/studio/auth/github/callback` Redirect URI，不使用通配符。

验收：分析页不依赖第三方密钥；评论/双语未配置时不阻塞构建；所有新增路由通过构建和链接检查；Vercel 产物不包含后台页面、API 函数或 Keystatic/Studio bundle。

运维实现、备份保留期、恢复和 OAuth 配置步骤见 [Studio 运维手册](./studio-operations.md)。
